## Research findings and applicability

The upstream [decomp-permuter](https://github.com/simonlindholm/decomp-permuter)
targets late register-allocation differences, warns that structural/functional
changes suit it poorly, and ignores stack positions unless requested. Its
documented architectures omit SH-2. We have a custom adapter; its diagnostic
score should not substitute for linked-byte validation or silently hide pools.

[Tokyo Bus Guide's findings](https://github.com/lhsazevedo/tbg-decomp/blob/main/docs/lessons_learned.md)
show concrete cases where decompiler variable reuse or guessed prototypes hid
the real arguments and values. Testing the original object exposed these.
That project pursues functional equivalence, so its rewritten C and coverage
exclusions are not recipes for our exact matching goal.

[sh4objtest](https://github.com/lhsazevedo/sh4objtest) makes expected calls and
writes explicit. It is an SH-4 tool, not a drop-in SH-2 solution. Its testing
pattern is useful for strengthening our existing harness. Use genuine game
states, boundary inputs, explicit call contracts and ordered effects; consult
[MAME's debugger](https://docs.mamedev.org/debugger/index.html) for real execution
observations. Keep the ROM hashes as the final acceptance gate.

The [IDO compiler decompilation](https://github.com/decompals/ido-matching-decomp)
is a concrete precedent for studying the compiler's optimizer/code generator to
help game decompilation. This does not supply SHC's algorithms. My recommendation
is a bounded SHC investigation, not a claim that an existing tool solves it.
[C-Reduce](https://github.com/csmith-project/creduce) can minimize examples while
preserving a chosen interestingness predicate. Reduced compiler experiments
remain diagnostic; they must never become fabricated production context.

The [Hitachi compiler manual](https://antime.kapsi.fi/sega/files/shccomp.pdf)
documents normal arguments in R4-R7. The later official
[SuperH compiler manual](https://www.renesas.com/en/document/mat/superh-cc-compiler-assembler-optimizing-linkage-editor-users-manual-ade-702-372a)
shows division lowering that moves arguments into R0/R1 before __divls. This
corroborates our ROM-specific private-ABI evidence; the later manual alone does
not identify our exact runtime version or source language.

   216D0 literal order, and259EA current/old index lifetimes. Include previously
   matched functions as controls. Preserve real enclosing sources, actual roots,
   stack layout and literal dependencies. Record exact native differences and
   failed hypotheses in one deduplicated index.
2. Reduce diagnostic examples and inspect SHC's decisions. The installed v5.0r32
   includes separate shcgen.exe (395KiB) and shcmdl.exe (228KiB). Trace the driver
   and identify which stage owns the observed register/pool choices; binary
   analysis or instrumentation is a next experiment, not an established fix.
   Derive predictions and test them on held-out examples before applying source
   changes. Keep the production compiler binaries unmodified.
3. Reconstruct compilation-unit boundaries from genuine BSR/JSR evidence and
   literal sharing. The local permuter already preserves head/tail context;
   validate that the context itself is correct. Prior successful save and medal
   work demonstrates that this can unlock multiple complete functions.
4. For larger semantic mismatches, strengthen targeted differential tests before
   permutation. Start with field57D4/5B80 and spawn61D0, using observed inputs and
   explicit effects. Tests must distinguish deliberately wrong source behaviour.
   Passing these tests permits better search prioritization, not C credit.
5. Use informed, bounded multi-process compiler searches only after the mismatch
   is classified. Track register-use/lifetime, frame, root, literal and raw-byte
   components separately. Retain full context and check real linked bytes for
   candidate acceptance. A lower scalar score is not progress by itself.
6. Resolve runtime feasibility as its own engineering task: identify the exact
   SHC library members/options, inspect available original package sources, and
   test whether supported C can express each private ABI without wrappers or
   opcode substitution. This checkout currently contains compiler executables,
   not evidence of matching runtime source. No such source was located in this
   bounded online research.

## The literal100% issue

The1,638-byte runtime region remains counted and unmatched. Solving every other
byte would yield199060/200698 =99.18385% C. Recovering original runtime assembly
or library objects can establish provenance but cannot honestly turn that into
100% compiler-produced C. Current evidence exposes a real ABI obstacle; it does
not prove universal impossibility. The active goal remains literal100%, with no
exception or reclassification silently introduced.

The useful immediate deliverable is a tested explanation of one SHC allocation
or pool mechanism that fixes a real target and generalizes to another, rather
than another large set of isolated spelling experiments. This is a proposed
strategy grounded in research and local evidence, not a promise of completion.
